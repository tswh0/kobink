Consistency is a feature

Filed under interfaces, history.

Every GEM application had the same menu bar: the program name on the left, then File, then Edit, then whatever else the program needed, with Help on the far right. That was not a limitation. It was a promise: learn one program, and you have learned the shape of all of them.

The same promise shows up in smaller things. A button that opens a dialog ends with an ellipsis. A disabled item is greyed out instead of hidden. The default button is the positive one, unless the action cannot be undone. Alerts say what happened and what to do next, in that order.

What to steal

  • One visual language for chrome; colour only for meaning.
  • Hard 1px edges, 16px rows, no gradients, no shadows.
  • Menus that stay in the same place in every window.
  • Dialogs that name the thing they are changing.

None of this needs a framework. The whole interface below is a stylesheet and a handful of semantic elements — buttons, fieldsets, selects, and a menu built from lists.
