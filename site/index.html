kobink

Your own Kobo store

Kobo only downloads from Kobo. Kobink answers at that address instead, and hands out the EPUBs already sitting in a folder on your machine. There is a shelf in the browser too, for when the device is not at hand.

A Kobo asks its store what it owns. Kobink replies with the files in your library, and the reader treats it as a normal sync. No account, no upload, no database.

Install

1. Start the container

PUBLIC_URL has to be an address the reader can reach, because it ends up inside every download link. If the device can open it in a browser, it is right.

services:
  kobink:
    image: ghcr.io/tswh0/kobink:latest
    restart: unless-stopped
    user: "1000:1000"
    ports: ["3000:3000"]
    environment:
      PUBLIC_URL: http://192.168.1.10:3000
    volumes:
      - /path/to/books:/library:ro
      - ./data:/app/data

Run chown -R 1000:1000 ./data once, so the container can write the key file.

2. Read the key

The first start generates the key and prints it together with the endpoint.

docker compose up -d
docker compose logs kobink

3. Point the reader at it

Edit .kobo/Kobo/Kobo eReader.conf on the device, then press Sync.

[OneStoreServices]
api_endpoint=http://192.168.1.10:3000/PASTE-YOUR-KEY-HERE/kobo

The path stops at /kobo. The device appends /v1 itself.

Read in the browser

Open the same address on a phone or a desktop and paste the key. The library is the root: a shelf of covers, and a tap opens the book, paginated for EPUBs and page by page for the fixed-layout kepubs KCC makes.

Position goes both ways. Where you stop on the device is where the browser opens, and a page turned in the browser reaches the device at its next sync. If the two disagree, the book with the most pages read wins.

It is an extension of the Kobo, not a reader of its own: no highlights, notes, dictionary or library management. Added to a phone's home screen it opens full screen. A fixed-layout book can be saved from the reading bar and read with no connection; progress made offline lands on the server at the next open.

Drop a book

Upload lives at /drop: drag EPUB, CBZ or PDF, several at once. EPUB is copied as it is; CBZ and PDF are converted for the reader you pick, which needs the bigger image and a writable library:

    image: ghcr.io/tswh0/kobink:conversion
    volumes:
      - /path/to/books:/library:rw

Deleting a book on the reader moves the file into .kobink-trash/ inside the library. LIBRARY_TRASH=off deletes it outright.

What it does

  • Covers are cut out of each book at the sizes the device asks for.
  • KCC books are advertised as KEPUB and fixed-layout books as EPUB3FL, which is what keeps manga filling the page.
  • Volumes arrive as a series with the right numbering, from the book's metadata or from its title (Fire Punch v03).
  • A sync with nothing new answers [] in a few kilobytes.
  • The key sits in the URL path. Everything outside it answers 404.
  • No database. One container, two folders.

Notes

  • The library is read again every ten minutes: drop a file in, wait, sync. LIBRARY_REFRESH_SECONDS=0 turns the timer off.
  • The container runs as uid 1000, so the library has to be readable by that user.
  • Reading progress is one JSON per book in .kobink-progress/, and goes with the book when it is deleted.
  • COVER_CACHE_DAYS and TRASH_DAYS (default 30, 0 keeps forever) prune the cover cache and the trash.
  • HTTP on your own network is fine. Behind a proxy, use HTTPS and keep the link to yourself. Offline copies need HTTPS or localhost, since service workers do not run on plain HTTP; the reader works either way.
  • API_KEY picks the key yourself instead of the generated one.
